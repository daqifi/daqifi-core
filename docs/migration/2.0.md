# Migrating from Daqifi.Core 1.x to 2.0

Version 2.0 removes, renames and re-types public members. This guide says what replaced each one.

- [Before you start](#before-you-start): framework, firmware, trimming.
- [The changes most callers need](#the-changes-most-callers-need), with code.
- [Reference by area](#reference-by-area): every removed, renamed or re-typed public member, and what behaves differently.
- [If you implement Core's interfaces or derive from its classes](#if-you-implement-cores-interfaces-or-derive-from-its-classes).
- [MCP server](#mcp-server): changes on the `Daqifi.Mcp` wire.

The guide is written against 1.10.0, the last 1.x release. Coming from an older 1.x, upgrade to 1.10.0
first and clear its `[Obsolete]` warnings: 2.0 deletes everything 1.x had marked obsolete. Recompile
everything that references Daqifi.Core; an assembly built against 1.x does not run against 2.0.

## Before you start

| | 1.x | 2.0 |
|---|---|---|
| Target framework | `net9.0` and `net10.0` | `net10.0` only. .NET 9 is out of support |
| Minimum firmware | 3.5.0 | 3.5.0, unchanged ([ADR 0001](../adr/0001-firmware-feature-gating.md)). Older devices still connect, but nothing is promised for them. Branch on `device.Supports(...)`, not on version text |
| Trimming | The assembly was not marked, so apps that trim only marked assemblies (the iOS and Android default) kept it whole | Marked trimmable and NativeAOT-compatible. If you reach its types by reflection (a XAML reflection binding, for example), add `<TrimmerRootAssembly Include="Daqifi.Core" />` to the app ([ADR 0003](../adr/0003-packaging-and-frameworks.md)) |
| Strong name | None | None, and there will not be one |

## The changes most callers need

Work down this list first. It covers what an application that discovers, connects, streams, logs and
updates firmware runs into.

### Namespaces

Three `using` changes. The types are the same apart from what the [export](#export) table lists.

| 1.x | 2.0 |
|---|---|
| `using Daqifi.Core.Logging.Export;` | `using Daqifi.Core.Export;` |
| `using Daqifi.Core.Device.Protocol;` | Delete it. `ProtobufProtocolHandler` and `ProtobufMessageType` are in `Daqifi.Core.Communication.Messages` |
| `DaqifiOutMessage` in the global namespace | `using Daqifi.Core.Communication.Messages;` |

### Connect

The blocking `Connect...` factories are gone.

```csharp
// 1.x
using var device = DaqifiDeviceFactory.ConnectTcp("192.168.1.100", 9760);
```

```csharp
// 2.0
await using var device = await DaqifiDeviceFactory.ConnectTcpAsync("192.168.1.100", 9760);
```

`device.Connect()`, `device.Disconnect()` and `device.Dispose()` are still there.

### Discover

There is one `DiscoverAsync`, which takes a timeout and a token. Reaching the timeout returns what was
found; cancelling always throws.

```csharp
// 1.x
using var finder = new WiFiDeviceFinder();
using var window = CancellationTokenSource.CreateLinkedTokenSource(cancellationToken);
window.CancelAfter(TimeSpan.FromSeconds(5));
IEnumerable<IDeviceInfo> found = await finder.DiscoverAsync(window.Token);
```

```csharp
// 2.0
using var finder = new WiFiDeviceFinder();
IReadOnlyList<IDeviceInfo> found = await finder.DiscoverAsync(TimeSpan.FromSeconds(5), cancellationToken);
```

### Connection state

`Status` and `State` were two answers to one question. There is now one `State` with one event, and
`Ready` means initialized.

```csharp
// 1.x
device.StatusChanged += (sender, e) => Console.WriteLine(e.Status);
bool usable = device.Status == ConnectionStatus.Connected;
```

```csharp
// 2.0
device.StateChanged += (sender, e) => Console.WriteLine($"{e.PreviousState} -> {e.CurrentState}");
bool usable = device.IsConnected;
```

Do not translate the check to `State == DeviceState.Connected`: an initialized device is `Ready`.

### Channels and outputs

Channel state is read-only, the commands take the kind of channel they work on, and the `...Async`
twins that only sent the command are gone.

```csharp
// 1.x
var ai0 = device.GetChannelsSnapshot().First(c => c.Type == ChannelType.Analog && c.ChannelNumber == 0);
await device.EnableChannelAsync(ai0);

var dio3 = device.GetChannelsSnapshot().First(c => c.Type == ChannelType.Digital && c.ChannelNumber == 3);
device.SetDioDirection(dio3, ChannelDirection.Output);
device.SetDioValue(dio3, true);

device.SetAnalogOutput(0, 2.5);
```

```csharp
// 2.0
var channels = device.GetChannelsSnapshot();
var ai0 = channels.First(c => c.Type == ChannelType.Analog && c.ChannelNumber == 0);
device.EnableChannel(ai0);

var dio3 = channels.OfType<IDigitalChannel>().First(c => c.ChannelNumber == 3);
device.SetDioDirection(dio3, ChannelDirection.Output);
device.SetDioValue(dio3, true);

var dac0 = channels.OfType<IAnalogOutputChannel>().First(c => c.ChannelNumber == 0);
device.SetAnalogOutput(dac0, 2.5);
```

### Start, stop and stream samples

The sync `StartStreaming()` and `StopStreaming()` have not changed. The `...Async` pair now waits for the
device to confirm and throws `DeviceCommandFailedException` when it does not. `StreamSamplesAsync`
takes its token last.

```csharp
// 1.x
await device.StartStreamingAsync(cancellationToken);
await foreach (var sample in device.StreamSamplesAsync(cancellationToken))
{
    Console.WriteLine(sample.Sample.Value);
}
```

```csharp
// 2.0
await device.StartStreamingAsync(cancellationToken); // throws unless the device confirmed the stream
await foreach (var sample in device.StreamSamplesAsync(cancellationToken: cancellationToken))
{
    Console.WriteLine(sample.Sample.Value);
}
```

### Raw messages

All three raw-message events have a sender and a typed message.

```csharp
// 1.x
device.StatusMessageReceived += message => Console.WriteLine(message.DeviceSn);
device.MessageReceived += (sender, e) =>
{
    if (e.Message.Data is DaqifiOutMessage message)
    {
        Console.WriteLine(message.MsgTimeStamp);
    }
};
```

```csharp
// 2.0
device.StatusMessageReceived += (sender, e) => Console.WriteLine(e.Message.DeviceSn);
device.MessageReceived += (sender, e) => Console.WriteLine(e.Message.MsgTimeStamp);
```

### Metadata

`device.Metadata` is an immutable snapshot that the device replaces. Read it again to see an update. If
you keep your own copy, replace it instead of writing to it.

```csharp
// 1.x
var metadata = new DeviceMetadata();
metadata.CopyFrom(device.Metadata);
metadata.FriendlyName = "Bench 3";
```

```csharp
// 2.0
var metadata = device.Metadata with { FriendlyName = "Bench 3" };
```

### SD card logging

There is one start. It logs the channels that are enabled and returns the file name it used.

```csharp
// 1.x
var recording = await device.StartSdCardLoggingSessionAsync("run.bin", channelMask: "3");
device.SetSdCardMinimumFreeSpace(100_000_000);
```

```csharp
// 2.0
var analog = device.GetChannelsSnapshot().Where(c => c.Type == ChannelType.Analog);
device.DisableAllChannels();
device.EnableChannels(analog.Where(c => c.ChannelNumber is 0 or 1));
var recording = await device.StartSdCardLoggingAsync("run.bin");
await device.SetSdCardMinimumFreeSpaceAsync(100_000_000);
```

### Firmware update

```csharp
// 1.x
await updater.UpdateFirmwareAsync(device, hexPath, progress, null, locationKey, cancellationToken);
await updater.UpdateWifiModuleAsync(device, packagePath, progress, cancellationToken, skipVersionCheck: true);
```

```csharp
// 2.0
var target = new FirmwareUpdateTarget { LocationKey = locationKey };
await updater.UpdateFirmwareAsync(device, hexPath, target, progress, cancellationToken);
var options = new WifiUpdateOptions { SkipVersionCheck = true };
await updater.UpdateWifiModuleAsync(device, packagePath, options, progress, cancellationToken);
```

### Errors

The exceptions in which the device refused or failed share a base, with the device's own reply on it.

```csharp
// 1.x
try
{
    await device.SaveAdcCalibrationAsync();
}
catch (DeviceCommandFailedException ex)
{
    Console.WriteLine(ex.DeviceResponse);
}
```

```csharp
// 2.0
try
{
    await device.SaveAdcCalibrationAsync();
}
catch (DaqifiDeviceException ex) // also SD card, diagnostics, not-supported, ...
{
    Console.WriteLine(ex.RawDeviceResponse.FirstOrDefault());
}
```

### Device

On `IDevice`, `DaqifiDevice` and, where it has the member, `BootloaderSessionDevice`.

| 1.x | 2.0 |
|---|---|
| `ConnectionStatus`, `IDevice.Status`, `DaqifiDevice.Status`, `BootloaderSessionDevice.Status` | `DeviceState` and `State`, on all three |
| `device.Status == ConnectionStatus.Connected` | `device.IsConnected` |
| `ConnectionStatus.Connected` | `DeviceState.Connected`, `Initializing`, `Ready`, `InitializationFailed` or `Disconnecting`; `state.IsConnected()` covers all five |
| `ConnectionStatus.Disconnected` | `DeviceState.Disconnected`, or `DeviceState.Disposed` once disposed |
| `ConnectionStatus.Connecting`, `Lost`, `Retrying`, `Failed` | The same names on `DeviceState` |
| `DeviceState.Error` | `DeviceState.InitializationFailed` |
| `DeviceState.Streaming` | Removed; nothing ever set it. Read `IStreamingDevice.IsStreaming` |
| `IDevice.StatusChanged`, `DaqifiDevice.StatusChanged`, `BootloaderSessionDevice.StatusChanged` | `StateChanged` |
| `DeviceStatusEventArgs`, `DeviceStatusEventArgs.Status` | `DeviceStateChangedEventArgs`, with `PreviousState` and `CurrentState` |
| `DeviceErrorSource.StatusNotification` | `DeviceErrorSource.StateNotification` (same value) |
| `IDevice.IpAddress`, `DaqifiDevice.IpAddress`, `BootloaderSessionDevice.IpAddress` | `(device as INetworkAddressedDevice)?.IpAddress`. Every device the factory connected over TCP or WiFi implements it; a serial one does not |
| `DaqifiDevice.StatusMessageReceived`, `DaqifiDevice.StreamMessageReceived` as `Action<DaqifiOutMessage>` | `EventHandler<MessageReceivedEventArgs>`: `(sender, e) => Use(e.Message)` |
| `MessageReceivedEventArgs.Message` as `IInboundMessage<object>`, and `new MessageReceivedEventArgs(IInboundMessage<object>)` | `DaqifiOutMessage` in both; `e.Message.Data as DaqifiOutMessage` becomes `e.Message` |
| `IDevice.MessageReceived`, `IDevice.ErrorOccurred` declared non-nullable | Declared nullable |
| `DateTime Timestamp` on `DeviceErrorEventArgs.Timestamp`, `ReconnectAttemptEventArgs.Timestamp`, `ReconnectedEventArgs.Timestamp`, `ReconnectFailedEventArgs.Timestamp` | `DateTimeOffset`, still UTC; `.UtcDateTime` gives the old value |
| `new DaqifiDevice(name, ipAddress, logger)`, `new DaqifiStreamingDevice(name, ipAddress, logger)` | To connect, `await DaqifiDeviceFactory.ConnectTcpAsync(ipAddress, port)`. These constructors never connected to the address; they are now protected and take no address |
| `new DaqifiDevice(name, stream, ipAddress, logger)` | Protected, without the address. Pass an `IStreamTransport`, or derive |
| `DaqifiDeviceFactory.ConnectTcp(...)` (both overloads), `DaqifiDeviceFactory.ConnectSerial(...)` (both overloads), `DaqifiDeviceFactory.ConnectFromDeviceInfo(...)` | `ConnectTcpAsync`, `ConnectSerialAsync`, `ConnectFromDeviceInfoAsync` |
| `DaqifiDeviceRegistry.Register(DaqifiDevice, ...)`, `DaqifiDeviceRegistry.Remove(DaqifiDevice)`, `DaqifiDeviceRegistry.TryGetDevice(key, out DaqifiDevice?)` | The device is a `DaqifiStreamingDevice` |
| `DeviceRegistration.Device`, `DeviceRegistrationResult.Device`, `DuplicateDeviceCheck.NewDevice` as `DaqifiDevice` | `DaqifiStreamingDevice`; drop the cast |
| `((DaqifiDevice)device).Supports(f)`, `.InitializeAsync()` | On any `IDevice` |
| `((DaqifiDevice)device).RefreshDeviceStatusAsync()`, `.ReadCapabilityDocumentAsync()` | On any `IStreamingDevice` |
| `((DaqifiStreamingDevice)device).SetFriendlyNameAsync(...)`, `.SetIdentifyAsync(...)`, `.GetIdentifyAsync()` | Also on `IDeviceIdentification`: `if (device is IDeviceIdentification id) await id.SetIdentifyAsync(true);` |

Behaviour:

| 1.x | 2.0 |
|---|---|
| A lost, retrying, given-up or disposed device reads `State == DeviceState.Disconnected` | `DeviceState.Lost`, `Retrying`, `Failed` or `Disposed`. Use `!device.IsConnected` for "no session" |
| `State` is `DeviceState.Connected` during a teardown | `DeviceState.Disconnecting` |
| No event for initialization, for the start of a teardown, or for disposal | `Initializing` then `Ready`, `InitializationFailed` or (cancelled) `Connected`; `Disconnecting` then `Disconnected`; `Disposed` |
| `Connected` announced once per connect | Also after a cancelled initialization; `PreviousState == DeviceState.Connecting` is the connect |
| Changes could be announced out of order, and a change made in a handler was raised before that call returned | Raised in order, one at a time, after the handler returns. A handler must not wait for a later event |
| Every event of a connect or disconnect raised while it runs | Only `Connecting` and `Disconnecting`; the outcome is raised once another connect or disconnect may start. A handler of those two must not block on a connect or disconnect made on another thread |
| `DisconnectAsync` raises its event on a pool thread | `Disconnecting` may be raised on the caller's thread |
| A throwing subscriber keeps later subscribers from hearing a state change | Every subscriber hears it; failures arrive on `ErrorOccurred`. On `BootloaderSessionDevice` they are swallowed |
| `DeviceState` values `Error` = 6 (and `ConnectionStatus` values `Lost` = 3, `Retrying` = 4, `Failed` = 5) | `InitializationFailed` = 5, `Disconnecting` = 6, `Lost` = 7, `Retrying` = 8, `Failed` = 9, `Disposed` = 10. Check values stored as numbers |

### Metadata and capabilities

`DeviceMetadata`, `DeviceCapabilities` and `DeviceHealth` are sealed records: `init`-only, equal by value,
and safe to share.

| 1.x | 2.0 |
|---|---|
| Setters `DeviceMetadata.PartNumber`, `.SerialNumber`, `.FirmwareVersion`, `.HardwareRevision`, `.DeviceType`, `.FriendlyName`, `.HostName`, `.IpAddress`, `.MacAddress`, `.Ssid`, `.DevicePort`, `.WifiSecurityMode`, `.WifiInfrastructureMode`, `.Capabilities`, `.Health`; `.CapabilityDocument` was set by Core only | `init`: `metadata = metadata with { Ssid = ssid }` |
| Setters `DeviceCapabilities.AnalogInputChannels`, `.AnalogOutputChannels`, `.DigitalChannels`, `.HasSdCard`, `.HasUsb`, `.HasWiFi`, `.HasWincWifiModule`, `.MaxSamplingRate`, `.SupportsStreaming` | `init`: `metadata with { Capabilities = metadata.Capabilities with { HasSdCard = false } }` |
| Setters `DeviceHealth.BatteryPercent`, `.BoardTemperatureCelsius`, `.DeviceStatus`, `.PowerStatus` | `init` |
| `DeviceMetadata.CopyFrom(source)` | `metadata = source` |
| `DeviceCapabilities.Clone()`, `DeviceHealth.Clone()` | Use the instance itself |
| `uint DeviceMetadata.WifiSecurityMode` | `WifiSecurityType?`. Not reported or not known: `null`. Open network: `None` |
| `uint DeviceMetadata.WifiInfrastructureMode` | `WifiMode?`. Not reported or not known: `null`. An old `(WifiMode)` cast compiles and throws on `null`; use `??` or `is { } mode` |
| `DeviceMetadata.UpdateFromProtobuf(message)` | Removed. In a subclass, `OnStatusMessageReceived(message)` |
| `DeviceMetadata.ApplyCapabilityDocument(document)`, `CapabilityDocument.MergeInto(capabilities)` | Removed; `ReadCapabilityDocumentAsync()` applies the document. In a subclass that stands in for a device, `UpdateMetadata(m => m with { CapabilityDocument = document, Capabilities = capabilities })` |
| `CapabilityDocumentParser` | Removed; `ReadCapabilityDocumentAsync()` |

Behaviour:

| 1.x | 2.0 |
|---|---|
| `var m = device.Metadata;` and later reads of `m` see updates | `m` is a snapshot; read `device.Metadata` again |
| Writing to `device.Metadata` changed what `Supports()` and the rate cap answered | Cannot be written. Tests derive and call `UpdateMetadata(m => m with { ... })` |
| `WifiSecurityMode` 0 for both "open" and "not reported"; a legacy 4 | `WifiSecurityType.None` and `null`; 4 reads as `WpaPskPhrase` |
| `metadata.Capabilities = null` was replaced with a new instance | Not replaced; a nullable warning |
| `CapabilityDocument.Channels`, `CapabilityStreaming.Encodings` and `.Transports` kept the list assigned | A read-only copy is taken on assignment; build the list first |

| 1.x | 2.0 |
|---|---|
| A DIO or PWM command given a non-digital channel throws `ArgumentException` | Does not compile |

### Streaming

| 1.x | 2.0 |
|---|---|
| `ILiveSampleSource.StreamSamplesAsync(ct, bufferCapacity)`, `DaqifiStreamingDevice.StreamSamplesAsync(ct, bufferCapacity)` | `StreamSamplesAsync(bufferCapacity, ct)`; `StreamSamplesAsync(ct)` becomes `StreamSamplesAsync(cancellationToken: ct)` |
| `IStreamingDevice.EnforceStreamingFrequencyCap()`, `DaqifiStreamingDevice.EnforceStreamingFrequencyCap()`, `SampleRateCap.EnforceOn(device)` | Removed; `StartStreaming` applies the cap. `MaximumStreamingFrequencyHz` is the limit, and `SampleRateCap.Enforce(rate, cap)` computes a capped rate |

Behaviour of the `...Async` members, which now complete only once the device confirmed. The sync members
are unchanged and are the way to get the old behaviour.

| 1.x | 2.0 |
|---|---|
| `IStreamingDevice.StartStreamingAsync` completed once the command was sent, or with no frame and no error | Completes on a new frame or on the device saying it streams; otherwise `DeviceCommandFailedException` |
| `StartStreamingAsync` completed at once when already streaming, or when another caller stopped the stream | Confirms the running stream; throws `OperationCanceledException` when another caller stops it, `DeviceNotConnectedException` when the connection ends |
| `StartStreamingAsync` within 100 ms of a stop sent at once | Waits out the rest of the 100 ms |
| `StopStreamingAsync` did nothing when not streaming, and returned once the stop was queued | Always sends the stop and waits for the device's answer. If another caller's start overtakes it, throws `OperationCanceledException` |
| `RebootAsync` returned once the command was queued and the link closed | Stops a running stream, waits for the acknowledgement, and stays connected if the device refuses. Over WiFi a reboot that did happen can still throw as unconfirmed |
